Fictotech CISO Incident Report: Hybrid Identity and Cloud Compromise

Verdict: True Positive - High Severity

Prepared for the CISO. Vectra evidence shows an incident that began with command-and-control activity on a datacenter collaboration server, moved laterally to a jump station using adam_admin, and then expanded into M365, Entra ID, Azure, and AWS through adam_admin@fictotech.com.

Executive Summary

The incident should be treated as a confirmed high-severity hybrid compromise. Vectra detected C2-like HTTPS tunneling from marketing-collab-server0, internal SMB/LDAP reconnaissance, remote service execution into jump-station5, repeated C2-like tunneling from the jump station, further lateral movement, privileged share access, and then a cloud-control-plane sequence using adam_admin@fictotech.com.

The cloud activity included suspicious sign-ons, automated scripting across Azure and M365, suspicious Copilot access, OAuth consent to Thunder Jaw Backdoor, mailbox-rule persistence, AWS organization/IAM enumeration, AWS access-key creation for another admin user, Azure Key Vault privilege assignment, storage/key-vault secret access, and Azure diagnostic logging disablement.

Business impact assessment: Potential exposure of cloud secrets and storage keys, persistent access through OAuth/mailbox rules/AWS access keys, impaired Azure diagnostic logging, and lateral movement from datacenter systems. No containment or state-changing action was taken by this assistant.

Likely Attack Narrative

The most defensible interpretation is a multi-stage intrusion. An operator established or used an HTTPS tunnel from marketing-collab-server0, performed SMB and LDAP discovery, then used adam_admin to execute services on jump-station5. The same external tunnel pattern appeared on jump-station5 shortly afterward, followed by remote execution to another internal host, scanning, and anomalous high-privilege share access. The identity then became active across SaaS and cloud control planes, showing automation, OAuth and mailbox persistence, AWS discovery and key creation, Azure privilege changes, secret access, and logging impairment.

The density and order of events, the cross-domain nature of the activity, and the use of multiple external source IPs make benign administration unlikely. The incident should be handled as an active or recently active compromise until containment and forensic validation are complete.

Recommended Executive Actions

  1. Declare or continue formal incident response handling and assign accountable owners for identity, endpoint, cloud, and communications workstreams.
  2. Preserve Vectra evidence, EDR telemetry, Entra ID sign-in/audit logs, M365 unified audit logs, AWS CloudTrail, Azure Activity Logs, Key Vault logs, and storage account logs before disruptive containment where possible.
  3. With human approval, contain adam_admin@fictotech.com: revoke sessions and refresh tokens, rotate credentials, review MFA methods, and disable or restrict the account until forensic review completes.
  4. Remove or disable the suspicious OAuth application and mailbox rule after preserving evidence; search for the same app, scopes, and rule pattern across other users.
  5. Rotate exposed or potentially exposed AWS access keys, Azure storage account keys, Key Vault secrets, certificates, and service principal credentials touched during the incident window.
  6. Investigate marketing-collab-server0 and jump-station5 with EDR and forensic tooling, focusing on 2026-05-15 13:20Z-18:30Z, service creation, outbound HTTPS to 40.121.154.127, and lateral movement artifacts.
  7. Review AWS account 073942728427 for persistence, unauthorized keys, role changes, new users, CloudTrail tampering, and data access following 19:13Z.
  8. Restore and validate Azure diagnostic logging on affected resources, then run a retrospective search for activity during the visibility gap.

Conclusion

The evidence supports a confirmed, high-severity compromise spanning on-premises lateral movement and cloud identity/control-plane abuse. The priority is to preserve evidence, contain the compromised identity and affected hosts with approval, remove persistence, rotate exposed secrets, and validate whether cloud data or secrets were accessed or exfiltrated.
